# 兩儀輸入法

不用按 Shift 就能中英混打的繁體中文注音輸入法（大千鍵盤），整句看前後文自動選字，選過的字詞會記住。
Windows 10／11（64 位元），原生 TSF 輸入法（C++）。

## 安裝
1. 到 [Releases](https://github.com/kenny824319/DualityIME/releases) 下載最新的 **`DualityIME-X.Y.Z-setup.exe`**
   （X.Y.Z 是版本號；標著 Pre-release 的是測試版）。
2. 雙擊執行，在跳出的視窗按「是」允許系統管理員權限。只有這一個檔案，放在哪個資料夾執行都可以；
   安裝不需要網路，**絕不會自己重新開機**。
   - 安裝檔沒有數位簽章：Windows 若顯示「Windows 已保護您的電腦」，按「其他資訊」，再按「仍要執行」。
3. 第一次安裝會把兩儀輸入法加進鍵盤清單，但**不會設成預設輸入法**：用 `Win + 空白鍵` 切換過去，
   想一開始就用它，到設定視窗「一般」頁打開「設為預設輸入法」。Windows 原本的切換快捷鍵（`Ctrl + Shift`、`Alt + Shift`）不會被改動。

安裝檔會：
1. 檢查 Windows 版本（Windows 10 或 11，64 位元）。
2. 把程式放到 `C:\Program Files\DualityIME`、向 Windows 登錄、登錄到「設定 > 應用程式」、在開始功能表加上「兩儀輸入法設定」。
   - 正被程式使用的舊檔先改名移開，新檔立刻放上：之後打開的程式就是新版，已經開著的程式關掉再開就換新；
     改名的舊檔在下次開機時自動清掉，不需要特地重新開機。
   - 安裝失敗時恢復成安裝前的版本，輸入法照樣能打字。
3. 第一次安裝時加進鍵盤清單（Windows 11 24H2 以後放在「中文(香港)」底下，更早的 Windows 放在「中文(台灣)」；
   打出來的都是繁體中文），其他語言和輸入法不會動到。之後再安裝或更新，鍵盤清單和預設輸入法都照你原本的設定。

**從智慧輸入升級**：直接執行新的安裝檔就好，不用先移除。打字記憶、校正與代碼記憶、個人詞庫和設定都會自動搬過來，
鍵盤清單和預設輸入法維持原狀，舊版的程式會清乾淨（你自己解壓縮的舊版資料夾不會刪）。
這台電腦的其他帳號，第一次用兩儀輸入法時也會自動搬過來。智慧輸入匯出的備份檔也能在「關於」頁匯入。
升級完成後請登出 Windows 再登入（或重新開機）：在那之前，已經開著的程式還載著舊版，裡面打字可能會卡住或打不出中文；安裝程式不會自動登出或重新開機。

### 版本與更新
版本號是 X.Y.Z：正式版是 X.Y.0，測試版從 X.Y.1 往上數。設定視窗「關於」頁顯示目前裝的版本；
按 **檢查更新** 向 GitHub Releases 查詢，再顯示最新的正式版和 beta 版（打開頁面時不連網）。有比目前新的版本時，
按鈕變成 **立即更新**：下載那一版的安裝檔、確認檔案完整，再執行安裝（Windows 會詢問一次權限），裝好後確認版號。
失敗時維持原本的版本，頁面上顯示錯誤代碼 `U-xxx`，「回報問題」會開啟 GitHub 的問題回報頁。

勾選 **搶先體驗測試版（Beta）**：更新時連測試版一起看，否則只看正式版。只會更新到比目前新的版本，不會降版。
也可以直接到 Releases 下載新版安裝檔執行，效果相同。

### 移除
- 設定視窗「關於」頁的 **解除安裝**（可選擇一併刪除學習紀錄、詞庫與設定；電腦裡還裝著 PIME 的，也可以一起移除 PIME），
- 或「設定 > 應用程式 > 兩儀輸入法」，
- 或在命令提示字元執行 `"C:\Program Files\DualityIME\uninstall.exe" --uninstall`（加 `--remove-data` 連學習紀錄一起刪除，
  `--remove-pime` 移除 PIME，`--all` 兩者都做；安裝檔 `DualityIME-X.Y.Z-setup.exe --uninstall` 也一樣）。

移除後鍵盤清單會留著中文(台灣)，原本的預設輸入法會改回來；為兩儀輸入法加的中文(香港)會拿掉。

## 功能
- **中英混打**：直接打 `hello `，打不出合法注音的字串自動當成英文；有大寫字母的字（如 `Python`）一定是英文。開著 Caps Lock 也照樣分辨中英，英文打出來是大寫；這時按著 Shift 打的字母才一定是英文。
  中英怎麼切開由一個評分模型決定（不是逐條規則）：字典裡的英文字便宜、字典外的字母串每個字母都有代價、
  英文後面直接接注音要付一次「切換」代價、越常用的注音音節越便宜，挑總分最好的切法。
  例如 `pythong4` = python是、`setup.exea87` = setup.exe嗎、`dog4`、`python3` 維持英文。
  分數的參數用 `tools/tune_english.py` 在英文單字、純注音句子與實測華碩的混打例子上調出來。
  少數同時是英文和注音的字（`up ` = 因）：前面是英文（`look up `）就當英文，否則預設中文；把游標移到它前面，
  上方的替換列有 `up`，選過會記住。字典裡三個字母以上的英文字加空白一定是英文（`look `、`google `）。
- **整句到 Enter 才送出**（同華碩智慧輸入法）：中文、英文、標點都留在同一段有底線的組字裡，按 Enter 一次送出。
- **整句選字、看前後文**：小麥注音的詞庫（約 14 萬個詞），加上從約 2 億字的維基百科與網頁文章統計出的
  「哪個詞後面常接哪個詞」（300 萬組詞對）。例如「可以」後面的 ㄕˋㄕˋ 是「試試」。上一次送出的最後一個詞也會當作前文。
- **會學習**：用 ↓ 選過的字詞下次會優先出現；連續選的單字（「華」＋「碩」）會自動記成新詞。
  很久沒用的會慢慢淡掉：每 20 天沒再用到，份量就減半；學到的詞、記住的英文字各最多留 2000 筆（留最常用的）。
  記住的 e-mail 不會淡掉，最多留 2000 筆（超過時丟掉最久沒用的）；網址不記。
- **替換列**（同華碩智慧輸入法）：游標移到某個字前面，文字上方自動出現一排其他寫法，按 ↑ 進入、← → 選、Enter 確定。
  例如「好」（`cl3`）有 `ㄏㄠˇ`（注音文）、`c襖`（前面照打、後面轉中文）、`clˇ`、`cl3`（照原本按鍵）；
  「版」（`103`）有 `ㄅㄢˇ`、`1俺`、`10ˇ`、`103`。選過的可以再從替換列改回來。
  替換列看的是游標後面的按鍵，不管目前怎麼切：游標停在英文字裡任何一個鍵前面，從那裡開始能讀成的注音字都會列出來，
  可以跨進後面那個字的按鍵（`sugatau,4au04` 被讀成 `sugatau,4面` 時，游標在 `u` 前面就有「業」，選了變成 `sugata頁面`）。
  所以不論自動判斷成什麼，都能一個字一個字改成要的切法。選了之後只固定那個字從哪個鍵到哪個鍵，其餘重新轉換
  （「頁」和「面」照樣合成「頁面」），游標接著跳到下一個字。
- **組字中逐字編輯**：← → 在中文一次移一個字，在英文、數字一次移一個鍵；Backspace／Delete 刪游標前／後，中間打字會插入。
- **個人詞庫**（設定視窗的「個人詞庫」頁）：
  - **自訂詞彙**：人名、專有名詞等，打字時優先出現。注音可以按「填入注音」自動查，破音字自己改。
    注音文（ㄅㄨㄚ、ㄏㄏ）也可以加，不用填注音：打它的鍵（`1j8`、`cc`）再按 ↓ 就會出現。
    也可以加英文字（`Kazuma`，不用注音）：中英混打時一定當英文，打開頭三個字就能用 Tab 補完。
  - **映射詞彙**：替一段文字（地址、常用回覆，最多 255 字）取個捷徑（英文字母和數字，或中文，最多 8 個字）。
    打出捷徑後按 ↓ 就出現那段文字；只打開頭幾個字會列出所有符合的。一邊是中文時兩個方向都能用
    （KFC → 肯德基：打「肯德基」按 ↓ 也會出現 KFC）。
  - 兩者都存在 `%APPDATA%\DualityIME\dictionary.json`。
- **匯出與匯入**（設定視窗的「關於」頁）：選字記憶、個人詞庫和設定匯出成一個 .json 檔，換電腦時直接匯入還原。
  匯入是合併：可以勾選要匯入哪幾項，這台電腦上已有的不會被刪除或改掉，同一個檔案匯入兩次也不會重複累加。
  記憶由輸入法引擎合併（設定工具把它放在 `import-memory.json`，引擎下一個按鍵時併進 `user.json`）。
- **框選查詢**：選取一段文字後連按兩次 `Ctrl`，跳出小視窗顯示注音（依詞判斷破音字），可以朗讀，
  也可以直接加進自訂詞彙或快捷文字。選取的文字透過 UI Automation 讀取，不會動到剪貼簿；
  有些程式不提供選取的文字，這時查不到。英文只能朗讀，沒有翻譯。
- **Tab 智慧補字**：文字後面用小框顯示最可能的**下一個字**（打「台」顯示「灣」），按 `Tab`（或在句尾按 `→`）採用，可以一直按下去。
  英文字、常打的英文字和記住的 e-mail 則顯示還沒打的部分（`abc` → `c12345678@gmail.com`；打過兩次的 `claude`，打 `cla` 就顯示 `ude`）。
  在 cmd、Windows Terminal 等終端機裡，小框也一樣接在文字後面（用 UI Automation 找出游標所在的格子）。
- **符號鍵盤**：按 `` ` `` 或 `~` 跳出符號虛擬鍵盤（一般／數學／特殊三頁），按鍵盤上的鍵就打出那個鍵上的符號，也可以用滑鼠點。
  `` ` `` 在英文後面也會叫出鍵盤；要打 `` ` `` 本身就連按兩下。英文字後面的 `~` 照打（`~/` 這類路徑）。
  按住空白處可以拖曳並記住位置。
- **單按 Shift 切換中／英**：切到全英文模式時工作列圖示變成「A」；Ctrl+Shift、Alt+Shift 不算。
  可以設定只用左邊或只用右邊的 Shift（另一邊就只是打大寫用）。
- **全形模式**：`Shift + 空白鍵` 切換，英文字母、數字、標點和空白都打成全形（`ＡＢＣ１２３`），會記住。
- **Ctrl + 標點打全形**（設定裡打開，預設關閉）：中英混打時按住 Ctrl 再按 `, . ; ? [` 這類標點鍵，打出 `，。；？「`；打開後，程式裡用這些組合的快捷鍵（例如 `Ctrl + ,`）在中英混打時會失效。
- **標準（大千）鍵盤**：只支援標準排列（ㄅ 在 1、ㄆ 在 Q，聲調在 6 3 4 7）。
- **注音文**：還沒打聲調的注音按 ↓，最後一個候選字是注音符號本身（`1` → ㄅ、`su` → ㄋㄧ）。
  拼不成字、會被當成英文的（`1j8` = ㄅㄨㄚ、`cc` = ㄏㄏ）：游標移到它前面按 ↑，替換列有注音文；選過一次，下次打完按 ↓ 就有。
  被當成英文的字（英文後面的 `a`），把游標移到它前面按 ↑，替換列第一個就是注音符號（ㄇ），同華碩智慧輸入法。
- **注音自動校正**（預設關閉，在設定的「打字」頁打開）：打錯的注音自動改成最可能的字：
  - 按到旁邊的鍵：`si3cl3` = 你好（u 按成 i；前後要有中文，單打 `si3` 可能是英文，不改）；
    `rup qu0 ` = 今天（w 按成 q：「今篇」不成詞、「今天」成詞才改；原本打的已經成詞的不改，例如「你老」）。
  - 注音順序打錯：`817` = 吧、`cl3817` = 好吧（187 打成 817，跟單打 `187` 一樣是吧，要數字按 ↓ 最後一個）；
    夾在中文中間的要跟前後組成詞才改（「有813個」還是數字），接在英文後面（`you are 817`）或更長的數字（`8173`）也還是數字。
  - 同一個鍵按兩次：`ssu3`、`su33` = 你。

  像英文的字（字典裡的字、記住的英文字、有大寫的、e-mail、`setup.exe`、`look up` 的 up）不會被改。
  偶爾會把打對的字或數字也改掉：游標移到那個字按 ↓，有原本那個字，最後一個是原本打的按鍵。
  **會記住你的習慣**：同一串按鍵改回原樣 2 次（例如常打房號 `817`），以後就照打的讀；
  沒被校正的地方（單打 `si3`、「有813個」的 813）按 ↓ 也會列出校正後的字，選同一個 2 次，以後就直接校正。
  久沒用會慢慢淡掉（每 20 天減半）。
- **記住英文代碼**（不用設定，注音自動校正開不開都有）：`mp3`、`ps4`、`x86` 這類字母加數字的代碼剛好拼得出注音時會被讀成中文
  （`mp3` = 允）。游標移過去按 ↑，從替換列選回原本的按鍵，同一串按鍵 2 次之後就一直是英文；接在英文後面被拆開的
  （`look gpt4` = look gp赤）會連前面的英文一起記成 `gpt4`，後面直接接中文的（`win10是`）選過 2 次也會記住。
  記錯了：游標移到它上面按 ↓，第一個是記住之前的讀法，選 2 次就改回來。
  這兩種記憶存在 `%APPDATA%\DualityIME\keys.json`；匯出與匯入的「記憶」、「補字與記憶」頁的「全部清除」都包含它。
- **遊戲模式**（預設關閉，在設定的「一般」頁打開）：打開後，Windows 認得的遊戲（遊戲列記得的，
  `HKCU\System\GameConfigStore`）和全螢幕獨佔執行的程式自動不組字，按鍵直接給遊戲，也不會跳出任何視窗
  （避免全螢幕遊戲閃爍）；在遊戲的聊天框要打中文，單按一下 Shift，再按一下回到不組字。
- **注音順序不限**：`us3` 和 `su3` 都是「你」。
- **上排數字鍵可以直接打數字**：不是注音的（`2026`、`100`）一定是數字；剛好也是注音的看有沒有打聲調：
  `18` + 空白 = 八、`104` = 辦；沒打聲調（`18` 直接 Enter）或前面是英文（`you are 18 `）就是數字。
- **預覽顯示英文字母＋注音提示**（同華碩智慧輸入法）：注音還沒打完時，文字裡顯示按的鍵（`su`），下面另外用小框顯示注音（ㄋㄧ），打完聲調才變成中文。可改成只顯示按的鍵，或在文字裡直接顯示注音。
- **設定工具**：安裝後在開始功能表的「兩儀輸入法設定」，或工作列的輸入法圖示按右鍵 >「兩儀輸入法設定」。跟著 Windows 淺色／深色模式，
  改了就自動儲存（`%APPDATA%\DualityIME\config.json`）：全形模式、標點與空白全形／半形、預覽方式、
  注音自動校正、遊戲模式、補字、個人詞庫、框選查詢、候選字大小與排列。
  「使用說明」有教學動畫（打注音、中英混打、↓ 換字、Tab 補字）和功能介紹卡片，「關於」可以檢查更新。
  它是一個網頁畫面（`settings/ui`）放在 Windows 內建的 Edge 網頁元件（WebView2）裡，外殼 `settings.exe`
  （`installer/src/Settings.cs`）幫它讀寫設定、詞庫與 Windows 的輸入法設定；畫面只載入本機檔案，只有按「檢查更新」時才連網。

學習紀錄、記住的英文字和 e-mail 都只存在這台電腦的 `%APPDATA%\DualityIME`。
e-mail **用兩儀輸入法打過一次**（在任何程式裡、送出後）就會記住，英文字（4 個字母以上）在中英混打時**打過兩次**就會記住，
下次打出開頭三個字就會出現補字提示；
用 Shift 切到全英文模式時打的、或貼上的文字不會被記住，網址也不記（照樣當英文輸出，只是沒有 Tab 補完）。
單一個字母（例如 `t`）從替換列選回原本的按鍵，只改那一次，不會從此都當成英文。
「補字與記憶」頁的「全部清除」清掉所有打字記憶：選字習慣、被當成英文的按鍵、記住的英文字、自動校正與代碼記憶；
設定與個人詞庫保留。記住的 e-mail 預設留著，勾選「一併清除記住的 Email」才一起清掉。

## 按鍵
| 按鍵 | 作用 |
|---|---|
| 空白、6、3、4、7 | 一～五聲 |
| Enter | 送出 |
| ↓ | 候選字：游標後那個字開頭的詞與單字（在句尾是最後一個字），再按 ↓ 往下、1–9 直接選；打完快捷文字的捷徑按 ↓ 出現內容 |
| →（候選字視窗裡） | 往右展開成多欄（同華碩智慧輸入法：一欄 9 個、一次 4 欄）；↑ ↓ ← → 移動、1–9 選標示編號的那一欄、PgDn / PgUp 換 4 欄；在第一欄按 ← 收合 |
| ↑ | 進入文字上方的替換列（游標在字前面時），← → 選、Enter 確定 |
| ← → | 移動游標（中文一個字、英文數字一個鍵）；在句尾按 → 採用補字提示 |
| Backspace / Delete / Esc | 刪游標前 / 後一個 / 全部取消 |
| Tab | 採用文字後面的補字提示 |
| Shift（單按） | 切換中文／全英文 |
| Shift + 空白鍵 | 切換全形／半形 |
| Ctrl 連按兩下（先選取文字） | 框選查詢 |
| `` ` `` 或 `~` | 符號鍵盤（Tab 換頁，Esc 關閉；`` ` `` 連按兩下打出 `` ` ``） |
| `, . ;`（接在中文後） | 標點，不會被當成注音 ㄝ ㄡ ㄤ |
| 標點與符號鍵 | 半形（預設）照打（`, < ! ?`）；全形：，。？！… |
| 數字鍵盤 | 一律是數字本身；打字中途按也不會中斷，直接加進正在打的句子。選字清單打開時，跟上排數字一樣用來選字 |

## 開發
- C++：需要 Visual Studio Build Tools（C++ 桌面開發）。`cpp\build.cmd [Release|Debug] [x64|x86]` 建置，
  `cpp\publish.cmd` 建置 Release 版並放進 `bin\`。
- `powershell -ExecutionPolicy Bypass -File installer\build.ps1`：建置 `bin\settings.exe`、`bin\lookup.exe`（開發用）；
  加 `-Release`（先執行 `cpp\publish.cmd`）建置安裝檔 `out\DualityIME-<VERSION>-setup.exe`。
- `py -3 .claude/scripts/check.py`：完整檢查（Python 引擎測試、C++ 建置、兩套引擎逐鍵比對、設定工具、安裝檔邏輯、發版腳本）。
- `py tools/compare.py [數量] [種子]`：同一批按鍵在 5 組設定下餵給 Python 和 C++ 引擎，每一步都必須相同。
- `py -3 -m unittest tests.test_engine`：引擎測試。
- `powershell -ExecutionPolicy Bypass -File tools\test_settings.ps1 [-Source]`：設定工具寫入的設定與詞庫、舊版資料轉換、更新流程
  （假的 Release 清單，不連 GitHub；暫存資料夾）、每一頁都畫得出來；`-Source` 從原始碼編譯來測，不檢查畫面。
- `powershell -ExecutionPolicy Bypass -File tools\test_setup.ps1`、`tools\test_release.ps1`：安裝檔與發版腳本的邏輯（不安裝、不發版）。
- `powershell -ExecutionPolicy Bypass -File cpp\tools\e2e.ps1 [cases.txt] [-Config file.json]`：在真的文字框裡打字測試
  （學習紀錄用暫存資料夾，跑完刪除）。
- `py tools/demo.py "su3cl3" "ji3ap7"`：在終端機試打（每個參數一句）。
- `tools/build_lexicon.py`：從 [McBopomofo](https://github.com/openvanilla/McBopomofo) 的 `Source/Data` 重新產生 `data/lexicon.txt`。
- `tools/build_bigram.py data/bigram.bin 120 <parquet>...`：從語料重新產生前後文模型（每個檔案最多取 120 百萬字）。
- `tools/english_check.py`：1 萬個常用英文單字中有幾個會被當成注音（目前 77 個，多是 `pm`、`dj` 這類縮寫）。
- `py tools/tune_english.py [--search]`：中英切分的評分參數在三組資料上的表現（`--search` 找更好的參數）：
  英文單字加空白要維持英文、純注音句子要全部轉中文、混打例子要照預期（多數是實測華碩的結果）。
- `tools/evaluate.py <parquet> 1000 [--no-bigram] [--typed]`：用沒拿來訓練的文章測正確率。目前結果（1000 句，從按鍵開始打）：

  | 測試文字 | 不看前後文 | 看前後文 |
  |---|---|---|
  | 維基百科 | 89.3% 字對 / 42.7% 整句對 | 96.3% / 72.1% |
  | 一般網頁 | 94.2% / 61.0% | 97.1% / 76.9% |

### 發版
分支：在本機的 feature 分支開發，驗證完併進 `develop`；`main` 是正式版。發版用 `tools\release.ps1`：

```
powershell -ExecutionPolicy Bypass -File tools\release.ps1 -Channel develop|main -Phase prepare|publish [-Repo 擁有者/名稱] [-Version X.Y.Z] [-WhatIf]
```

1. `-Phase prepare`：決定版號（`develop` 第三碼加 1；`main` 第二碼加 1、第三碼歸 0）、寫進 `VERSION` 並提交、跑完整檢查、
   建置安裝檔。`develop` 這次沒有改到會打包進安裝檔的東西（`cpp/`、`installer/`、`settings/`、`data/`、`VERSION`）時腳本什麼都不做（照樣可以推送，不建立 Release）。
2. 自己 `git push` 那個分支。
3. `-Phase publish`：建立 GitHub Release `vX.Y.Z`（`develop` 是 Pre-release），附上 `DualityIME-X.Y.Z-setup.exe`，
   說明從這次的提交訊息整理。tag 由 GitHub 建立；腳本不推送、不建本機 tag、不刪任何 tag 或 Release。
   `main` 發完會印出讓 `develop` 跟上 `main` 的指令（`git push origin main:develop`，或 `develop` 有自己的提交時先合併）。

`develop` 的 `-Phase prepare` 在 `origin/main` 有 `develop` 沒有的提交時會停下來（「main 有 develop 沒有的提交：先把 main 合回 develop」）：
正式版的版號只提交在 `main`，沒合回來的話測試版的版號會比正式版小。

`-WhatIf` 只印出會執行的指令；`-Version`（只用於 publish）照目前的版號發布、不加版號。

已知還會錯的：他/它（「它是一個很好的人」）、「我再一次逝世」這類要看更遠前文才分得出來的情況，見 `tests/test_engine.py` 的 `KnownHardTest`。
